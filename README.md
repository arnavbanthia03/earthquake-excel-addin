# Earthquake Data: Excel Task Pane Add-in

**Topic 12: Excel Add-in that Fetches API Data**

An Office Task Pane Add-in for Microsoft Excel, built with JavaScript and HTML. With one click, it fetches the latest earthquakes (past 30 days) from the public [USGS Earthquake API](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php) and writes them into an Excel worksheet.

## Features

- Fetches every earthquake USGS reported in the past 30 days (`all_month` feed)
- Writes 13 columns per earthquake: location, magnitude, magnitude type, time, latitude, longitude, depth, event type, status, tsunami flag, significance, alert level and a link to the USGS event page
- Writes the results to a dedicated worksheet called **Earthquakes**, so existing sheets are never overwritten
- Orange header row, columns auto-fitted
- Magnitude and depth are stored as real numbers, so Excel can sort, filter and chart them
- Newest earthquakes first
- Loading spinner, success and error messages, and buttons that disable during a fetch
- **Clear Sheet** button
- Readable error messages for network failures, HTTP errors and unexpected data

## Architecture Diagram

The task pane is a normal web page (HTML, CSS and JavaScript) that Excel displays in a side panel. It does two jobs: it talks to the **USGS API** over the internet to get data, and it talks to the **Excel workbook** through **Office.js** to write that data into cells.

```
+--------------------------------------------------------------+
|                       Microsoft Excel                        |
|                                                              |
|   +----------------------+        +----------------------+   |
|   |      Workbook        |        |      Task Pane       |   |
|   |   ("Earthquakes"     | <----> |   (our HTML/JS app,  |   |
|   |       sheet)         | Office |   served from        |   |
|   |                      |  .js   |   https://localhost  |   |
|   +----------------------+        |        :3000)        |   |
|                                   +----------+-----------+   |
+--------------------------------------------- | --------------+
                                                | fetch() over HTTPS
                                                v
                                   +------------------------+
                                   |   USGS Earthquake API  |
                                   |  (all_month.geojson)   |
                                   +------------------------+
```

### Flow of one button click

```
 [Fetch button]
      |
      v
 taskpane.js             showLoader() + disable buttons            (ui.js)
      |
      v
 fetchEarthquakes()      GET request to USGS, returns raw GeoJSON  (api.js)
      |
      v
 formatEarthquakeData()  GeoJSON -> 2D array                       (formatter.js)
      |
      v
 Excel.run(...)          write 2D array into the worksheet         (taskpane.js)
      |
      v
 hideLoader() + show "Loaded N earthquakes."                       (ui.js)
```

The 2D array that `formatter.js` produces looks like this, where the first row is the header and every row has the same number of columns:

```js
[
  ["Location", "Magnitude", "Mag Type", "Time", "Latitude", "Longitude", "Depth (km)",
   "Type", "Status", "Tsunami", "Significance", "Alert", "USGS Link"],
  ["10 km NE of Ridgecrest, CA", 2.4, "ml", "30/10/2026, 10:00:00 am", 35.7, -117.5, 6.1,
   "earthquake", "reviewed", "No", 89, "None", "https://earthquake.usgs.gov/earthquakes/eventpage/..."]
]
```

### Module contract

| Export | File | What it does |
|---|---|---|
| `fetchEarthquakes()` | `api.js` | Async. Returns the raw GeoJSON, or throws an `Error` with a readable message |
| `formatEarthquakeData(geojson)` | `formatter.js` | Returns a 2D array, row 0 is the header |
| `showLoader()`, `hideLoader()`, `setStatus(msg, isError)`, `setButtonsDisabled(bool)` | `ui.js` | Small DOM helpers |

## Setup Steps

### Prerequisites

- [Node.js](https://nodejs.org/) 18 or later (comes with npm)
- [Git](https://git-scm.com/)
- Microsoft Excel: desktop (Windows or Mac) or Excel on the web with a Microsoft account

### 1. Clone and install

```bash
git clone https://github.com/arnavbanthia03/earthquake-excel-addin
cd earthquake-excel-addin
npm install
```

### 2. Trust the local HTTPS certificate (one time only)

Office add-ins must be served over HTTPS, even on your own computer. This command creates a certificate for `localhost` and tells your machine to trust it:

```bash
npx office-addin-dev-certs install
```

Accept any prompts that appear.

### 3. Start the local web server

```bash
npm run dev-server
```

This starts the webpack dev server at `https://localhost:3000`. Leave this terminal open, because Excel loads the task pane from this address. To check it works, open `https://localhost:3000/taskpane.html` in a browser. You should see the page, though the buttons won't do anything outside Excel.

### 4. Sideload `manifest.xml` into Excel

Pick **one** of these options.

#### Option A: Let npm do it (easiest, Windows and Mac)

```bash
npm start
```

This starts the dev server, opens Excel and sideloads the manifest in one go. Stop it later with `npm stop`. If you use this option, you can skip step 3.

#### Option B: Excel on the web (works on any OS)

1. Keep `npm run dev-server` running.
2. Open a workbook at [office.com](https://www.office.com) (Excel).
3. Go to **Insert → Add-ins → More Add-ins → Manage My Add-ins → Upload My Add-in**.
4. Choose the `manifest.xml` file from the project root and click **Upload**.

#### Option C: Excel desktop on Windows (shared folder)

1. Create a folder such as `C:\AddinManifests` and copy `manifest.xml` into it.
2. Right-click the folder, choose **Properties → Sharing → Share**, and share it with yourself. Copy the network path, for example `\\YOUR-PC\AddinManifests`.
3. In Excel, go to **File → Options → Trust Center → Trust Center Settings → Trusted Add-in Catalogs**.
4. Paste the network path into **Catalog Url**, click **Add catalog**, tick **Show in Menu**, click OK, and restart Excel.
5. Go to **Insert → My Add-ins → SHARED FOLDER** and select **Earthquake Data**.

#### Option D: Excel on Mac

```bash
mkdir -p ~/Library/Containers/com.microsoft.Excel/Data/Documents/wef
cp manifest.xml ~/Library/Containers/com.microsoft.Excel/Data/Documents/wef/
```

Restart Excel, then go to **Insert → Add-ins → My Add-ins** and pick the add-in from the developer add-ins section.

### 5. Use the add-in

1. On the **Home** tab, click **Earthquake Data** to open the task pane.
2. Click **Fetch Latest Earthquakes**.
3. A sheet named **Earthquakes** appears, filled with the latest data.
4. Click **Clear Sheet** to empty it.

> **Windows PowerShell note:** older PowerShell versions do not support `&&`. Run each command on its own line.

## Research Questions

### 1. What are Office Add-ins and the manifest file?

Office Add-ins are small web apps that run inside Office programs like Excel, Word or Outlook. There is nothing to install on your computer the way you would install a normal program. An add-in is just a web page, built with HTML, CSS and JavaScript, that Office shows in a panel next to your document (this panel is called a task pane). Because it is a web page, it can do all the things a normal website can do, such as calling an API, and it also gets a special JavaScript library called Office.js that lets it work with the document itself.

The manifest is the file that connects the web page to Office. It is an XML file (ours is `manifest.xml`), and it works like an ID card for the add-in. It tells Excel:

- who the add-in is: its name, description, version, and a unique ID (a GUID)
- where the web page lives, which for us is `https://localhost:3000/taskpane.html` during development
- which Office program it supports, which is Excel (`Workbook`)
- what permissions it needs (we use `ReadWriteDocument`, because we write data into the sheet)
- which websites it is allowed to talk to (`AppDomains`, where we listed `earthquake.usgs.gov`)
- what button to show on the ribbon and what icon it uses

Excel doesn't contain our code. It reads the manifest, adds the button to the Home tab, and when you click it, Excel loads the page from the URL in the manifest. That also means we can change our code without touching the manifest, unless we change something like the URL or the permissions.

### 2. How does Office.js read and write cells?

Everything in Excel's Office.js goes through `Excel.run()`. Inside it, you get a `context` object, which is like a connection to the open workbook. You never touch the cells directly. Instead, you work with proxy objects, which are JavaScript stand-ins for things like worksheets and ranges. Changes you make to them are queued up and only sent to Excel when you call `await context.sync()`. That batching is a bit unusual at first, but it means Excel gets one bundled request instead of lots of small ones.

**Writing** is the easy part, and it is what our add-in does. You pick a range, then assign a 2D array to its `values` property. Each inner array is one row:

```js
await Excel.run(async (context) => {
  const sheet = context.workbook.worksheets.getItem("Earthquakes");
  const range = sheet.getRangeByIndexes(0, 0, table.length, table[0].length);
  range.values = table;      // queued, not written yet
  await context.sync();      // now it actually goes to Excel
});
```

This is why the formatter has to return a rectangular 2D array. If the array is 5 rows by 4 columns, the range we select must also be 5 by 4, or Excel throws an error.

**Reading** has one extra step. Because the range is only a proxy, its values are not in JavaScript yet. You have to ask for them with `load()`, then sync, and only after that can you use them:

```js
await Excel.run(async (context) => {
  const range = context.workbook.worksheets.getItem("Earthquakes").getRange("A1:D10");
  range.load("values");      // "I'll need the values"
  await context.sync();      // fetch them from Excel
  console.log(range.values); // now it's a 2D array
});
```

The most common beginner mistake is reading `range.values` before the `sync()`, which gives an error saying the property isn't loaded. In our project we also used `getItemOrNullObject` for the sheet. If the sheet doesn't exist yet, it returns an object with `isNullObject = true` instead of crashing, so we can create the sheet only when it's missing.

### 3. How do you sideload an add-in for testing?

Sideloading means loading an add-in straight from your own computer using the manifest file, without publishing it to the Microsoft store or an admin catalog. It is the normal way to test during development. The basic idea is the same everywhere: start a local web server so there is something to load, then tell Excel where your `manifest.xml` is.

For us the steps were:

1. **Start the local server** with `npm run dev-server`. It serves the task pane at `https://localhost:3000`. We first had to run `npx office-addin-dev-certs install` so that Excel trusts the HTTPS certificate, because Office refuses to load add-ins from plain HTTP.
2. **Give Excel the manifest.** How you do this depends on where you run Excel:
   - **Easiest:** run `npm start`. It starts the server, opens Excel and sideloads the manifest for you.
   - **Excel on the web:** go to *Insert → Add-ins → More Add-ins → Manage My Add-ins → Upload My Add-in* and pick `manifest.xml`.
   - **Excel desktop on Windows:** put the manifest in a shared folder, add that folder as a *Trusted Add-in Catalog* under the Trust Center settings, restart Excel, then open it from *Insert → My Add-ins → Shared Folder*.
   - **Excel on Mac:** copy `manifest.xml` into the `~/Library/Containers/com.microsoft.Excel/Data/Documents/wef` folder and restart Excel.
3. **Open it** from the Home tab, or from My Add-ins, and test it.

The dev server must stay running the whole time, because Excel loads the page from `localhost` each time you open the task pane. If you get a blank pane, it is almost always a server that isn't running or a certificate that isn't trusted. If the manifest gets rejected, `npm run validate` usually tells you what is wrong.

## Troubleshooting

| Problem | Fix |
|---|---|
| Blank task pane | Make sure the dev server is running. Open `https://localhost:3000/taskpane.html` in a browser, and if you see a certificate warning, re-run `npx office-addin-dev-certs install`. |
| "Module not found" when building | One of `api.js`, `formatter.js`, `ui.js` or `styles.css` is missing from `src/taskpane/`. Merge the teammates' branches. |
| CSS import error in webpack | Run `npm install --save-dev style-loader css-loader` and add `{ test: /\.css$/, use: ["style-loader", "css-loader"] }` to `module.rules` in `webpack.config.js`. |
| Spinner never goes away | `.hidden { display: none !important; }` is missing from `styles.css`. |
| Manifest not accepted | Run `npm run validate` and read the message. |
| "Network error" in the task pane | Check your internet connection and that `earthquake.usgs.gov` is reachable. |
| Add-in doesn't appear after sideloading | Restart Excel, and confirm the dev server is still running. |
| Fetch is slow or Excel feels sluggish | The 30-day feed can contain thousands of rows. Wait for the spinner to finish, or switch `api.js` to a smaller feed such as `all_week` or `2.5_month`. |
| Old icon still showing | Run `npm stop`, close Excel, clear the Office cache, then `npm start` again. |
| `&&` error in PowerShell | Run the commands on separate lines. |

## Data Source

Earthquake data comes from the [USGS Earthquake Hazards Program](https://earthquake.usgs.gov/) public GeoJSON feeds. This project uses the *past 30 days, all magnitudes* feed:

`https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_month.geojson`

Other feeds follow the same pattern (`all_hour`, `all_day`, `all_week`, or a magnitude filter such as `4.5_month`), so switching only requires changing the URL in `api.js`.
